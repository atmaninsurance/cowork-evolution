## A. `orchestrator.sh` — red-line gate (CLD-00085)

### A1 — scan surface (the defect)

`red_line_hit()` now takes **the artifact(s) under judgment** and nothing else. All four call
sites were changed to hand it only the proposal:

| call site | before | after |
|---|---|---|
| autonomous-dispose veto (`handle_fresh_intake`) | `red_line_hit "$spine" "$intake"` | `red_line_hit "$intake"` |
| auto-route gate (DEC-0082 choice-2) | `red_line_hit "$spine" "$intake"` | `red_line_hit "$intake"` |
| escalation `[red-line]` tag | `red_line_hit "$spine" "$intake"` | reuses the same single evaluation |
| rewrite re-verification gate (DEC-0082 choice-3) | `red_line_hit "$spine" "$sidecar"` | `red_line_hit "$sidecar"` |

The token list is **unchanged** (byte-identical pattern, hoisted to `RED_LINE_RE` so the
matcher and the diagnosis share one definition). `grep -inoE` was checked for match parity
with the old `grep -qiE` on the same pattern.

The function's header comment now states the invariant and why it exists: the spine is an
append-only findings record that accumulates V/D's own prose, so scanning it gives the gate a
feedback loop into itself; findings and proposals live in separate files and the gate reads
only the proposal.

### A2 — diagnosis

`red_line_hit()` records `RED_LINE_FILE` / `RED_LINE_LINE` / `RED_LINE_TOKEN` /
`RED_LINE_CONTEXT` for the match. On a fire the ledger now carries, e.g.:

```
red-line   FLAG — OI-000001 red-line gate matched 'COWORK-DECISIONS' in OI-000001.decision-01.md line 15 (decision sidecar under judgment; the spine is never scanned)
```

…and the run log carries the matched line's context (first 120 chars). No more reconstructing
a boolean.

### A3 — contradiction FLAG

`flag_clean_match_escalation()` fires when the verdict is the clean auto-route match
(`variation=none`, `recommend=route`, `questions=0`) and the item escalates anyway:

```
contradiction FLAG — OI-000001 escalated despite a CLEAN auto-route match (provenance=verified recommend=route variation=none questions=0) — blocked by: red-line gate ('COWORK-DECISIONS' in OI-000001.decision-01.md line 15)
```

Wired into **both** gates (fresh-intake auto-route and rewrite re-verification). The blocking
reason is named in every case — red-line, attester, routing failure, non-consultation origin,
provenance, `recommend=dispose`, `variation` — and the `reverify FAIL` ledger line now ends
with `blocked by: <gate>` too. An ordinary `variation=significant` escalation emits no FLAG
(asserted, section W2) — the FLAG stays rare enough to mean something.

### A4 — scope limit honored

No read-vs-write distinction was attempted. A task whose **own** content names a governance
file still escalates (asserted, section W). That refinement remains for the red-line DEC.

## C. `lint-transcripts.py` — sentinel continuity + two new checks (CLD-00086)

### C1 — the turn count is now scoped to the document's own turns

`own_turn_headers()` replaces the whole-text `TURN_RE.findall(text)`. Two independent
structural signals, applied only to **exporter-shaped** files (`tool-owned` +
`live-deterministic`), with fail-open at every step:

1. **Closed embedded-transcript spans** — a quoted transcript announces itself with a
   document header (`# Transcript:` / `**Chat ID:**`) below the file's own header block and
   ends at a **foreign** foot sentinel. Headers inside a *closed* span are embedded. An
   *unclosed* span is ignored: an open-ended exclusion could swallow the document's own later
   turns and invert the finding, the one regression this fix must not introduce.
2. **Own-sequence contiguity** — the exporter numbers a document's own turns 1..N with no
   gaps, so a header counts as own only if it continues the run. Quoted turns restart at 1 or
   jump (11..15) and drop out.

If scoping yields nothing while headers exist (e.g. `4586b77e`, a file whose only header is
`Turn 2`), the unscoped count is used — behavior identical to pre-fix. Hand-authored
transcripts are not scoped at all: their numbering is legitimately sparse (`local_7637cb93`
starts at Turn 9; `local_c41c193b` carries only a backfilled Turn 23), so contiguity would
have manufactured four new false findings there. **This ownership restriction is a judgment
call — see §Judgment calls 2.**

Measured over the whole 323-transcript corpus: sentinel-vs-turn mismatches **8 → 1**. The one
survivor is genuine legacy (`local_aa788c48`: sentinel AFTER_TURN_30, zero turn headers) and is
still reported. **Zero new findings anywhere.**

### C2 — diagnosis

A firing continuity check now reads:

```
<file>: sentinel AFTER_TURN_3 but highest OWN turn header is 5 (line 29); 14 embedded turn header(s) excluded as quoted content
```

— line number of the max own header, whether it sits inside a quoted/embedded region, and how
many headers were excluded.

### C3 — seed-staleness / missed-flush FLAG

`remote_` file **and** sentinel still `AFTER_TURN_0` **and** no `[SOFT-CLOSE]`/`[SWEEP]` marker
in the file's own foot region **and** header `Live capture started` date earlier than the
lint-run date → `FLAG missed flush — contingency fire never delivered …`. The marker condition
is what keeps a successful one-incomplete-turn soft-close (header-only *with* a marker) from
false-positiving; asserted both ways.

### C4 — contingency-ledger cross-check

A `remote_` transcript for the lint's target day with neither a ledger line nor a close marker
→ `FLAG fire never ran or bridge down …` (deliberately distinct text from C3).

**The ledger lookup reads ledger DATA LINES, not the ledger file.** The first implementation
substring-matched the whole file and reported a fire that never happened, because
`remote-contingency-ledger.md`'s own installation note *names* the chat that directed it —
the exact mention-vs-use error this build exists to kill, committed inside the fix for it.
Caught in fixtures; the check now parses `<YYYY-MM-DD HH:MM PT> | <chat id> | …` and requires
the date to match. A regression assertion locks it (`ledger PROSE naming a chat is not read as
a fire`).

### Scope discipline for all of C

Marker and sentinel tests read the document's own foot region (`text[-4000:]`) and the header
block (`text[:1500]`) — never a whole-text grep.

1. **C3/C4 FLAGs do not set the exit code.** They are reported on stdout, carried in the JSON
   summary as `flags`/`flags_count`, and written into the daily log's `[COMPACTION-ISSUE]`

   *integrity* violations. Reasoning: these describe the remote **delivery pipeline's** state,

   permanent data loss, and a non-blocking finding is the failure mode the wiki page calls the
